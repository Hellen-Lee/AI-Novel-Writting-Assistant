# draft 判定重构与首行成稿声明（261016）

> 前置：[`09-Agent原生工具调用.md`](../build/09-Agent原生工具调用.md)、[`260921-生成思考透传与结构化输出计划.md`](260921-生成思考透传与结构化输出计划.md)
> 代码：`backend/app/services/{generation_service,draft_sentinel}.py`、`backend/app/prompts/agent_system.md`、`backend/app/skills/*.md`；前端 `utils/paragraphs.js`、`components/editor/Agent/**`

本次记录为何把「本轮是正文还是闲聊」的判定从**事后启发式**换成**模型显式声明 + 分层判定**，以及由此引入的首行成稿声明契约。

---

## 1. 问题

Agent 自由文本路径下，**非创作内容（审阅/分析/建议）被归入 draft 草稿卡**，在编辑区渲染成
「AI 闲聊 · 待处理 / 将插入到正文末尾」，并带「插入 / 替换」按钮，可能被诱导写入正文。

复现路径：用户请模型评估某章完整性 → Router 判 `chat` → 模型按 `agent_system` 规则 3
（讨论时不要输出正文）输出长篇审阅分析 → 判定层仍判 `draft=True`。

### 直接原因

旧 `_decide_draft` 的两条启发式：

1. **`reads_work` 单信号成判**——只要调过 `read_chapter` / `read_recent_work` 就认定在写正文。
   而审阅分析**恰恰必须读稿**，必然中招。
2. **长度启发式**（`len(content) > 400`）——分析/建议天然超 400 字。

### 根因

- 判定层**没拿到 Router `decision`**（Router 已算出却未传入），于是 Router 判 `chat` 后
  启发式仍能翻盘，与 `agent_system` 规则 3 形成自相矛盾：**模型遵守了规则，判定层把它的
  正确答案判错。**
- `_resolve_content_anchor` 在判定为 draft 后**无条件复用前端选区锚**，于是「选段提问」
  会拿到「作用于第 X 段 → 可替换原段」的按钮，放大误导。
- `_preset_draft` 与 `_decide_draft` 逻辑重复、双 meta，前端会「气泡 → 突然跳成草稿卡」闪动。

---

## 2. 设计原则：误判代价不对称

判成非 draft 最坏是「用户少一个卡按钮、重新点一次续写」；判成 draft 会把分析写进正文、
产生脏数据。因此**默认偏非 draft，只允许模型显式升级**——与旧实现的「启发式自动升级」
方向相反。

---

## 3. 判定分层（`draft_sentinel.classify_output`）

依据可信度降序，替代旧的 `_decide_draft`：

| 序 | 信号 | 结果 |
| --- | --- | --- |
| 1 | 首行声明哨兵 `[[DRAFT\|...]]` 命中 | **prose** + 落点（模型显式声明，最强） |
| 2 | `preset ∈ DRAFT_PRESETS`（续写/润色/扩写） | **prose** |
| 3 | `preset ∈ BUBBLE_PRESETS`（生成设定） | chat |
| 4 | Router `decision ∈ {chat, clarify}` | chat（**不再被启发式翻盘**） |
| 5 | 无任何信号（Router 被跳过/报错） | chat（默认兜底） |

**删除**：`reads_work` 单信号成判、`DRAFT_PROSE_MIN_CHARS` 长度启发式、`tool_called` 标志（仅服务该判定）。
**新增校验**：仅当判定为 prose 时才接受选区锚。

---

## 4. 首行成稿声明（方案 B 落地）

复用既有 `[[ANCHOR|...]]` 哨兵体系的形态，但位置由末尾改为**首行**，并同时承载意图与落点：

```
[[DRAFT|insert_after|5]]      成稿插入到第 5 段之后
[[DRAFT|replace_range|1|5]]   成稿替换第 1–5 段
```

`HeadSentinelScanner` 是只在流**最开头**工作的状态机：

- 容忍前导空白/BOM/空行，以及被 ```` ``` ```` fence 包裹的演示范式；
- 首个正文正文字符出现即**封口**，之后不再扫描（正文中出现的同形文本原样保留）；
- 哨兵分片到达（`[[DRA` + `FT|...]]`）时继续缓冲，命中即剥离并把锚交给上层；
- 声明后紧随的空行即使落在下一个 delta 也会被吃掉；
- 段号非法（如 0）时不认声明，整段按正文透传；
- 超长无进展缓冲（512 字符）视为正文，避免异常输出把正文一直扣住。

命中后后端立即发 `{"type":"draft_hint",draft:true,content_anchor:{...}}`，草稿卡**在流式期间**
就渲染到目标段落，不再依赖末尾 meta 翻转，消除了气泡突跳。

末尾 `[[ANCHOR|...]]` **保留解析兼容**（模型可能仍输出），但 prompt 不再教模型使用。

---

## 5. 非成稿就是非成稿（不提供手动送入正文）

初版曾在前端给气泡加过「送入正文区」入口，作为模型漏声明时的安全网。**已移除**：

判定为「非成稿」之后再提供一条把它塞进正文的路径，与「默认偏非 draft」的原则
自相矛盾——那等于把刚判定掉的风险又请回来，用户仍可能把一段审阅分析写进稿件。
需要正文时，显式点续写/润色/扩写即可（这些 preset 自带成稿语义），或让模型
在首行输出成稿声明。非成稿回复保持**只读聊天气泡**。

---

## 6. 行为对照

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 点「续写」 | 草稿卡 | 草稿卡（不变） |
| 点「生成设定」 | 气泡 | 气泡（不变） |
| 选段提问「这段写得如何」 | **草稿卡 + 替换该段按钮** | 气泡（无按钮） |
| 自由输入「评估本章完整性」（读过正文、超 400 字） | **草稿卡** | 气泡 |
| 自由输入续写 + 首行声明 | 草稿卡（靠长度猜） | 草稿卡（显式声明，流式期即落位） |
| 自由输入长正文但未声明 | 草稿卡（靠长度猜） | 气泡（只读） |

## 7. 已知边界

- **代价**：模型漏声明且 Router 判 `chat` 时，正文落在气泡里，只能重新点续写。
  这是为「分析绝不污染正文」付出的确定性代价，属有意取舍——重新生成一次的
  成本，低于「一段分析被误插进稿件」的清理成本。
- 若模型先输出整段寒暄再写正文，首行状态机会封口而不命中，落回气泡。可通过 prompt
  强化首行契约缓解，不引入二次模型调用。
- 自由文本长正文的判定不再由长度决定，**可能出现更多「落在气泡」的情形**；依赖模型
  对首行声明的配合度，需用 Agent Viewer 观察命中率后再决定是否调 prompt。
- 首行状态机与末尾 ANCHOR 正则**并存**：旧输出仍可解析，不做破坏性移除。

## 8. 未采纳方案：工具调用声明 draft

曾考虑新增 `propose_draft` 工具让模型在工具决策轮声明，**未采纳**：

1. **预算失效**：工具决策轮 `TOOL_ROUND_MAX_TOKENS=1024`，推理模型会先吃掉大量
   reasoning token 导致 content 与 tool_calls 同时为空（见 `AGENTS.md` §9.1），
   把 draft 判定挂上去等于让它随机失效。
2. **时序倒置**：正文在**最终流式轮**才产生，决策轮只能「先声明、后书写」，
   声明与实际输出脱钩。
3. **默认值陷阱**：模型不调工具时仍要落回启发式，等于没修；而「不调工具」恰是出 bug 的场景。

留作远期**落点**升级项（结构化替代 ANCHOR 正则），不承担意图判定。

## 9. 验证

### 稳定复现指令

截图里的 bug 由两条旧启发式触发，因此能**稳定复现**的指令必须同时满足
「会读稿」且「输出足够长」。实测最稳的一条是：

> **请评估第一章的完整性，指出问题和修改建议。**

实测 3 次连续运行，每次都调 `read_chapter` + `get_outline`（有时还调 `search_memory`），
输出 890–1150 字 —— **旧逻辑必然判 `draft=True`，新逻辑稳定判 `False`**。

同族的可用变体（同样落在 bug 区间，但位数略短）：`评价一下这一章写得怎么样，有哪些问题？`、`这一章有什么不足？`。

> 为什么它会稳定触发：审阅分析**必须读稿**（命中 `reads_work` 单信号），
> 且**必然超过 400 字**（命中长度启发式）。两条路径同时成立，不依赖模型随机性。

自动复现脚本（自带合成稿件与临时项目，清理后退出）：

```bash
cd backend && python run.py                        # 另开终端启动后端
npm run test:draft                                 # = python backend/tests/repro_draft_misclassification.py
python backend/tests/repro_draft_misclassification.py --runs 3   # 验证稳定性
```

脚本每轮同时打印「实际 `draft`」与「旧逻辑会判成什么」，用于确认该轮确实落在
bug 区间（否则报「复现不成立」），并附带一条 `/续写` 正向对照（必须仍是草稿卡、
必须真正产出正文），避免修 bug 时把成稿路径改坏。

### 离线（不调真实模型）
