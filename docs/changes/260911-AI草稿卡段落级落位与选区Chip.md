# AI 草稿卡段落级落位与选区 Chip（260911）

## 背景

此前 `editor-page__ai-draft` 只能整块渲染在正文末尾：润色前五段时，草稿卡出现在章末，
用户无法直观看到"新文本将落在第五段后 / 替换掉前五段"。同时正文选区虽会随请求发给
模型，但输入框工作区没有任何可视化提示。

## 改动

### 1. 编辑区按锚点拆段渲染（核心）

- 新增 `frontend/src/components/editor/EditorCanvas.jsx`（+ 同名 css）：
  - `AutoGrowTextarea`：原 ChapterMain 的自动增高 textarea 抽成独立组件；
  - `AiDraftCard`：草稿卡（插入 / 替换 / 改写 / 弃用）原样迁入，类名与交互不变；
  - `EditorCanvas`：草稿有段落锚且落点不在文末时，把正文在 `anchor.endPara` 段后
    拆成上下两个 textarea，草稿卡渲染在两段之间（= 第 N 段之后、第 N+1 段之前）；
    无锚或落点在文末时维持原单 textarea + 末尾卡片。
- 新增 `utils/paragraphs.js` 的 `splitContentAt(content, paraCount)`：
  按原始字符偏移切出 `{ head, tail, tailBase, sep }`，不规整用户文本；
  `head + sep + tail` 与原正文逐字节一致；`tailBase` 用于下段 textarea
  选区偏移 → 全局偏移映射（`handleEditorSelect(e, baseOffset)`）。
- ChapterMain 画布区改为 `<EditorCanvas>`；textarea/草稿卡样式从
  `pages/EditorPage.css` 迁到 `components/editor/EditorCanvas.css`（类名不变）。

### 2. 流式期间即落位

`useAgentGenerate.syncDraft` 现在带上 `anchor: resolvedAnchor || undefined`
（请求时快照的选区锚 → meta 后模型哨兵锚覆盖），草稿卡在流式输出期间就渲染到
目标段落之后，而不是等生成完才跳位。

### 3. 选区进入输入框工作区

- InputBar 输入框上方新增 `SelectionChip`：显示"已选 第 a–b 段 · N 字"+ 单行预览，
  × 可清除选区（`onClearSelection` 由 EditorPage 经 EditorRightRail → AgentPanel 透传）。
- 选中文本随下一条消息/快捷指令一起发给模型（发送链路原有，本次只补可视化）。

## 行为对照

| 场景 | 之前 | 现在 |
| --- | --- | --- |
| 润色前五段（有选区或模型哨兵锚） | 草稿卡在章末 | 草稿卡落在第 5 段后、第 6 段前 |
| 插入 | 写入第 5 段后 | 同左（卡片位置即插入位置，所见即所得） |
| 替换 | 替换第 1–5 段 | 同左 |
| 续写无选区 | 卡在文末 | 不变 |

## 已知边界

- 草稿打开期间在锚点边界处（上段 textarea 末尾 / 下段 textarea 开头）敲空行会被
  分隔区"吸收"而不显示——在段中间换段不受影响；需要紧邻草稿卡上方新起段落时，
  可直接点「插入」或在下段 textarea 开头输入。
- 草稿打开期间编辑正文，锚段号不会随增删段落自动平移（既有行为，applyDraftByAnchor
  同样按应用时刻的正文重新切分）。
- 后端注入 `$current_content` 时不带段落编号，纯文字指令（"润色前五段"且无选区）
  依赖模型自行数段输出 `[[ANCHOR|replace_range|1|5]]` 哨兵；后续可在 prompt_builder
  注入带编号的正文以提高命中率。
