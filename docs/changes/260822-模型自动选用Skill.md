# 260822 · 模型自动选用 Skill（轻量路由回归）

> 架构说明：本文为迭代过程记录；本次改动在统一 agentic 路径之上**增加一层轻量「选 skill」路由**，与 `docs/changes/260822-Agent原生工具调用与移除Router.md` 中移除的 Router 定位不同（见 §1）。
> 代码：`backend/app/services/generation_service.py`；技能标记 `backend/app/skills/*.md`、`data/skills/*.md`；复用 `prompt_builder.build_router_prompt / parse_router_response / ROUTER_SYSTEM`。
> 前端无需改动：AgentViewer 已支持渲染 `router` 步骤；聊天气泡 `meta.skill_name/preset` 已消费。

---

## 1. 背景与定位

`260822-Agent原生工具调用与移除Router.md` 移除了**显式 Router 分流**（`meta.mode: router|skill|chat`、SSE `router_meta`），改为统一 agentic function-calling 路径——模型自行决定是否用工具读取章节/前文/大纲/记忆。该决策成立，本次**不推翻它**。

本次加回的是另一层、更轻的**「选 skill」路由**，二者不冲突：

| 维度 | 已被移除的 Router | 本次加回的轻量路由 |
| --- | --- | --- |
| 职责 | 自由输入分流到 续写/闲聊/澄清（主路径控制器） | 自由输入时从可自动调用 skill 目录**选一个注入其意图** |
| 产物 | `meta.mode`、`router_meta` 分流 | 一个 `mode:"router"` 的 run step；未命中不改路径 |
| 未命中时 | 走 chat 分支 | 原样走统一 agentic 自由文本路径 |
| 与工具调用 | 竞争关系 | 前置层，命中后仍可走原生工具 |

**动机**：自由输入（如「继续写主角看夕阳的内心」）此前不会自动命中「续写」等 skill 的意图/规则，只能靠用户点按钮或 `/续写`。加一层轻量路由后，模型可先判断最契合的 skill 并注入其意图（`preset_intent`），使自由文本也能享受 skill 的专属约束；判断不中（闲聊等）则无缝回落统一路径，成本只有一次 max_tokens≈120 的调用。

---

## 2. 实现

### 2.1 路由阶段（`generation_service.iter_generate`）

仅当 `skill_name` 未指定（`preset is None`）时触发：

1. 取候选 `skill_loader.list_skills(include_auto_invocable_only=True)`（过滤掉 `disable-model-invocation=true` 的 skill），得到 `allowed` 名字集。
2. 候选非空时，`build_router_prompt` 组装（薄上下文 + 历史 + 候选目录）→ `client.generate`（`max_tokens:120, temperature:0.0`）→ `parse_router_response(raw, allowed_names=allowed)`。
3. `decision == "skill"` 且 `skill_name ∈ allowed` → `preset = skill_name`、`preset_is_router = True`，复用下游 preset 路径（`preset_intent` 注入意图、`conversation_note` 历史处理、`_decide_draft` 判定）；meta 帧 `skill_name/preset` 即路由结果，前端气泡自动显示。
4. `decision == "chat"`（含解析失败/越界/无候选/路由报错）→ `preset` 保持 `None`，原样走统一 agentic 自由文本路径。
5. `decision == "clarify"` → 本次按 chat 处理（`ask_reply` 契约未接线，最小范围）。

路由决策记录为 `run_store.make_step("router", skill_source="router", candidate_skills=..., extra={decision, reason})`，并置于 steps 首位供 AgentViewer 观测。

### 2.2 skill_source 区分来源

把 `agent`/`agent_tool` 步骤的 `skill_source` 由硬编码 `"explicit" if preset else ""` 改为：

```python
_skill_source(explicit=not preset_is_router, skill_name=preset)
```

- 路由命中 → `"router"`
- 用户显式传 `skill_name` → `"explicit"`（行为与改动前一致）
- 纯闲聊（未命中）→ `""`

### 2.3 技能标记放开

将以下 skill 的 `disable-model-invocation` 由 `true` 改为 `false`（`skill_loader` 默认值仍为 `true`，此处为实际配置）：

- 内置：`backend/app/skills/` 下 续写、润色、扩写、生成设定
- 自定义：`data/skills/` 下 人物塑造、场景节拍

> 默认值 `true` 未变：新建自定义 skill 若不加显式 `disable-model-invocation: false`，仍不会进入自动选用候选（保持保守）。

---

## 3. 边界与排障

- **候选为空**：跳过路由模型调用，`preset=None` 走 chat；router step 记录 `decision="chat"`、`reason="no_candidates"`。避免一次空目录的无意义往返。
- **路由返回不在候选集的 skill**：`parse_router_response` 已降级 chat，另有 `skill_name in allowed` 双重保险。
- **路由模型调用失败**：捕获 `ModelClientError` → `decision=chat`，整轮不中断。
- **路由命中后的预算行为**：复用 `protect_user_body=True`（prose 场景，聊天历史不喧宾夺主），符合预设路径既有设计。
- **CRLF 注意**：`sed` 在 Windows 会把 skill 文件的 CRLF 行尾剥成 LF，导致整文件 diff 被污染；改标记后须把文件转回 CRLF 保持最小 diff。
