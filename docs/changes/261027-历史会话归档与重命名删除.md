# 历史会话：时间归档 · 重命名 · 删除 · 清空

> 日期：261027 · 设计稿：`docs/Novel.pen` → `Review/Sidebar/Agent-History`（`OckRz`）
> 关联：`docs/build/03-编辑页.md` §9、`docs/build/06-Agent生成与会话链路.md` §3

## 背景

编辑页右栏「历史会话」长期只是 `OckRz` 的**界面壳**：搜索框 `disabled`、只有「今天」一组真实数据、「昨天 / 更早」写着「分组逻辑待接入」、「清空历史」禁用、也没有重命名与删除入口。后端同期只有会话的列表 / 新建 / 详情 / 删除四个接口。本次把设计稿要求的归档与整理能力补齐。

## 设计取向（与设计稿的两处有意偏离）

| 项 | 设计稿 | 本次实现 | 理由 |
| --- | --- | --- | --- |
| 分组 | 今天 / 昨天 / 更早 | 今天 / 近 7 天 / 更早 | 「昨天」粒度太细，一周内的会话会被切成 7 段噪音；三分组更贴近回访节奏。空组不渲染，避免出现空标题 |
| 删除确认 | 稿面未画 | 自定义 `ConfirmDialog` | 与设计稿的 Modal 语言一致；项目删除仍用 `window.confirm`，本域不复用 |
| 重命名 | 稿面为菜单项 | 列表项行内输入框 | 少一次弹窗，Enter 提交 / Esc 取消 / 失焦提交，改名时能直接看到上下文 |

其余规格严格对齐 `OckRz`：头栏 48/14、搜索框 34 高圆角 8（icon 14 / placeholder 12）、会话行 `6 8` 圆角 8（`min-height: 36px` 固定行高，hover 出现「⋯」或进入行内重命名都不改变高度，列表不跳动）、行间距 4、激活态 `primary-soft` 底 + 左侧 3×20 圆角 2 强调条、标题 13（激活 600 / 常规 500）、hover 显示「⋯」24×24、下拉 128 宽（padding 4、项高 32、`0 10` padding、gap 8、文字 12、删除项 `trash-2` + `error` 色、阴影 `0 4 12 #1A2E281A`）、footer `10 14 12 14` 上边框 + 「共 N 条会话」11 muted + 「清空历史」。

## 后端

新增两个接口（`routers/sessions.py` + `api_catalog.py` 索引）：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| PUT | `/api/projects/{id}/agent/sessions/{sid}` | `SessionUpdateRequest{title}` → `SessionSummary`（不含消息正文）；空白 422、超 64 字截断、未知会话 404 |
| DELETE | `/api/projects/{id}/agent/sessions` | 清空全部会话 → `SessionClearResponse{deleted}` |

`session_store` 的两条关键取舍：

1. **重命名不刷新 `updated_at`**。若沿用 `save_session`，每次改名都会把会话顶到「今天」，历史归档就失去意义。`rename_session` 直接写盘并只更新索引摘要，顺序保持不变（有单测覆盖）。
2. **`title_locked`**。空会话发出首条消息时，`append_messages` 会用 `title_if_empty` 自动命名。用户已经手动命名过的会话若被首条消息覆盖，等于改名无效，因此重命名时置位、自动命名前检查。
3. **单删用 `_cleanup_session_assets`**（附件目录 + `run_store.delete_runs_for_session`），保证不留下「无会话的附件 / run」孤儿。**清空用 `_purge_session_assets`**整目录回收 `agent/{attachments,runs,reasoning}`：既避免逐个会话扫描 run 目录（O(n²) 文件读），也顺带清掉索引与会话文件都已丢失的孤儿数据；`agent/sessions/*.json` 先统一删除，索引缺失的残留会话也计入 `deleted`。
4. **重命名返回 `SessionSummary`**：改名只影响标题，返回整份 `SessionDetail` 会把全部消息正文再传一遍；前端 `renameRemoteSession` 相应改用 `mapSessionSummary`，只取标题更新列表项，不动已加载的消息。

## 前端

数据链路：

```
api/sessions.js            list / create / get / update / delete / clear
  → Agent/service/sessions.js   mapSessionSummary|Detail、renameRemoteSession（摘要）、clearRemoteSessions
  → Agent/hook/useAgentSessions.js  列表 + 激活会话 + 三类操作
  → useAgentPanel           透传，且重命名/删除/清空不切回对话态
  → shell/HistoryPanel      搜索 + 分组 + 确认框编排
      └ shell/HistorySessionItem  行按钮 + hover「⋯」+ 下拉 + 行内输入
```

四个交互决策：

- **删除/清空后不退出历史视图**：整理会话时连续操作更顺手；只有「点会话」「新建对话」才切回对话。
- **激活会话被删时自动接续**：切到下一条；若删空则立刻新建一条空会话（标题「新对话」），避免生成链路因没有 `session_id` 而报「会话未就绪」。
- **清空后再建一条**：同上，清空是「清空历史」而不是「禁用对话」。
- **切换/删除前静默中断生成**：`stopGeneration({silent:true})` 不再弹「已终止生成」，避免整理会话时出现误导性提示。

其他细节：

- `utils/historyGroups.js` 全部是纯函数（分组用日历天差、非法时间归「更早」），单测覆盖边界；标题过滤忽略大小写与首尾空白。
- 历史视图不渲染 InputBar，错误提示改用面板内 `historyError` 内联条；进入历史视图（`openHistory`）时清空上一条，避免旧错误滞留。
- `stopGeneration` 用 `useCallback` 稳定引用（它被放进 effect 与会话切换回调）；`{silent:true}` 不写提示。
- 新增 `components/ui/ConfirmDialog`（复用 `Modal`）+ `Button` 的 `danger` 变体，供后续删除类操作复用。
- 「⋯」下拉按滚动容器**上下边界**共同判断展开方向（`rect.bottom + 菜单高 > 下边界` 且 `rect.top - 菜单高 > 上边界` 才向上），贴顶的行不会被裁。

- `backend/tests/test_session_history.py`（12 例）：重命名持久化 / 不刷新 `updated_at` / 顺序不变 / 截断 / 空白报错 / 404；`title_locked` 阻止自动命名且未锁定时仍自动命名；`clear_sessions` 清理索引、会话文件、附件目录与 run；孤儿附件/run 在会话丢失时也被回收；索引缺失的残留会话文件计入 `deleted`；`summarize_session` 不含 `messages`；项目不存在 404。
- `frontend/.../utils/historyGroups.test.js`（10 例）：分组边界、空组剔除、标题过滤。
- `frontend/.../shell/HistoryPanel.test.jsx`（8 例）：分组渲染、搜索过滤与空结果、切换会话、行内重命名 Enter/Esc、删除与清空二次确认、无会话时清空禁用。
