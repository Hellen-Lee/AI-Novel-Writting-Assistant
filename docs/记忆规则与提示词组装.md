# 记忆系统、创作规则与提示词组装

> 本文档说明本地项目中的长期记忆、全局/临时规则如何存储，以及最终如何拼成发给大模型的提示词。  
> 实现以当前后端代码为准：`memory_store`、`project_store`、`prompt_builder`、`skill_loader`。

---

## 1. 总览

每次 AI 生成（续写、润色等）最终只向模型发送 **两条消息**：

| 角色 | 来源 | 内容 |
| --- | --- | --- |
| `system` | SKILL.md 的 `kind` 决定 | `quick_action`：frontmatter 里的 `system`；`skill`：固定为空字符串 |
| `user` | SKILL.md 正文模板 + 变量替换 | 记忆、规则、章节上下文、用户输入等全部经 `$变量` 注入 **用户消息** |

```
请求上下文
  ├─ settings.json（全局规则、文风）
  ├─ memory.json（长期记忆）
  ├─ chapters/（最近 3 章 + 当前章）
  ├─ 请求参数（选中文本、用户输入、临时规则）
  └─ SKILL.md（system + user 模板）
        │
        ▼  prompt_builder
  { system, user }  →  model_client → 大模型
```

要点：

- **记忆和规则不单独占一条 system 消息**；它们作为 `$global_rules`、`$worldview` 等占位符，出现在 skill 的 **user 模板**里。
- **system 只负责角色与任务约束**（如「你是专业小说作者……」），由各 SKILL.md 自己写死。
- MVP **不做向量检索**：记忆按分类全文格式化后注入（设定量可控时足够用）。

## 2. 相关文件位置

```
data/projects/{project_id}/
├── meta.json          # 项目元信息（与提示词无关）
├── settings.json      # 全局规则、文风偏好
├── memory.json        # 长期记忆
├── outline.json       # 大纲与章节列表
└── chapters/
    └── chapter_XX.md  # 章节正文（短期上下文）

backend/app/skills/    # SKILL.md 模板（含 system / user 正文）
```

## 3. 记忆系统（长期记忆）

### 3.1 存储文件

路径：`data/projects/{project_id}/memory.json`  
读写服务：`backend/app/services/memory_store.py`  
API：`GET/PUT /api/projects/{id}/memory`，以及按分类的条目增删改。

### 3.2 顶层结构

记忆按 **3 个分类** 存成对象；每个分类是条目数组。不允许出现未定义的分类键。

```json
{
  "worldview": [],
  "characters": [],
  "story_core": []
}
```

| 字段（分类） | 含义 | 典型用途 |
| --- | --- | --- |
| `worldview` | 世界观 | 世界规则、地理、力量体系等 |
| `characters` | 人物（含关系） | 姓名、简介、人物关系等，见 3.3.1 |
| `story_core` | 故事内核 | 核心主题、核心冲突、故事主线等 |

> **全本大纲不在 memory**：`outline.json` 的 `synopsis` / `volumes` 由设定库「大纲」栏维护，经 `prompt_builder` 注入 `$synopsis` / `$volumes`。  
> **人物关系不再单独分类**：关系挂在每个人物条目的 `relationship` 数组上。  
> 已弃用：顶层 `items`、`plot_points`、`relationships`；`load_memory` 懒迁移时丢弃并回写。

新建项目时写入空结构（各分类 `[]`）。

### 3.3 单条记忆字段

#### 3.3.1 人物条目（CharacterEntry）

人物与人物关系统一存在 `characters` 中：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 自动 | 条目 ID；缺省时生成 8 位 hex |
| `name` | string | **是** | 角色名；不能为空 |
| `profile` | string | 否 | 人物简介（性格、背景、能力等） |
| `relationship` | array | 否 | 关系列表，元素为 `{ type, target }`；默认 `[]` |
| `tags` | string[] | 否 | 标签（如「主角」「反派」）；默认 `[]` |
| `created_at` | string | 自动 | ISO8601 UTC 时间 |
| `updated_at` | string | 自动 | ISO8601 UTC 时间 |

`relationship` 单条字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | string | **是** | 关系类型，**允许中文**（如「母亲」「姐姐」「对手」）；原样存储，不做中英转换 |
| `target` | string | **是** | 对方角色名 |

结构示意：

```json
{
  "name": "林砚",
  "profile": "边陲少年，意外获残剑。性格坚韧、重情义。",
  "relationship": [
    { "type": "母亲", "target": "小红" },
    { "type": "姐姐", "target": "小高" },
    { "type": "对手", "target": "顾寒" },
    { "type": "同盟", "target": "苏晚" }
  ],
  "tags": ["主角"]
}
```

- 同一 `type` 可出现多条（如多个「朋友」）。
- UI 在角色编辑模态中按行维护：左栏 `type`、右栏 `target`，支持「添加关系」。
- 可选扩展（非 MVP）：`note` 字段补充说明（如「养母」）。

#### 3.3.2 其他分类条目（MemoryEntry）

`worldview` / `story_core` 使用通用条目：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 自动 | 条目 ID；缺省时生成 8 位 hex |
| `name` | string | **是** | 条目标题（如势力名、道具名）；不能为空 |
| `content` | string | 否 | 详细描述正文 |
| `tags` | string[] | 否 | 标签，便于筛选/展示；默认 `[]` |
| `created_at` | string | 自动 | ISO8601 UTC 时间 |
| `updated_at` | string | 自动 | ISO8601 UTC 时间 |

示例：

```json
{
  "worldview": [
    {
      "id": "a1b2c3d4",
      "name": "灵气复苏",
      "content": "近十年地球灵气浓度逐年上升，普通人亦可觉醒异能。",
      "tags": ["背景", "时代"],
      "created_at": "2026-07-24T08:00:00+00:00",
      "updated_at": "2026-07-24T08:00:00+00:00"
    }
  ],
  "characters": [
    {
      "id": "e5f6g7h8",
      "name": "林砚",
      "profile": "边陲少年，意外获残剑。性格坚韧、重情义，对剑道有独特悟性。",
      "relationship": [
        { "type": "对手", "target": "顾寒" },
        { "type": "同盟", "target": "苏晚" }
      ],
      "tags": ["主角"],
      "created_at": "2026-07-24T08:01:00+00:00",
      "updated_at": "2026-07-24T08:01:00+00:00"
    }
  ],
  "story_core": []
}
```

### 3.4 注入提示词时的格式化

`prompt_builder` 将每个分类格式化为多行文本（空则写成 `（无）`）。

通用分类（世界观 / 故事内核）：

```
- {name} [tag1, tag2]：{content}
```

人物分类额外展开关系：

```
- {name} [tag1]：{profile}
  关系：母亲→小红；姐姐→小高；对手→顾寒
```

即对 `relationship` 数组逐项格式化为 `{type}→{target}`，用 `；` 连接。无 `profile` 时只输出名称与标签；`relationship` 为空数组则省略关系行。

对应模板变量：

| 变量 | 来源分类 |
| --- | --- |
| `$worldview` | `memory.worldview` |
| `$characters` | `memory.characters`（含内嵌 `relationship`） |
| `$story_core` | `memory.story_core` |
| `$synopsis` | `outline.synopsis` |
| `$volumes` | `outline.volumes` |

> `$relationships` / `$items` / `$plot_points` 已废弃：旧自定义模板仍会渲染为 `（无）`，勿再写入新 SKILL。

### 3.5 与「短期上下文」的区别

| 层级 | 存什么 | 怎么进提示词 |
| --- | --- | --- |
| 长期记忆 | `memory.json` 结构化设定 | `$worldview` 等变量 |
| 短期上下文 | 最近章节 Markdown + 当前章正文 | `$previous_chapters`、`$current_content` |

最近章节规则：取当前章 `order` **之前**最多 3 章；若未指定 `chapter_id`，则取全书最后 3 章。格式为：

```markdown
### {章节标题}
{章节正文}
```

### 3.6 记忆进化（规划，非 MVP 强制）

字数/章节到达节点时，可由模型从新增正文提取候选设定，**弹窗经用户确认后再写入** `memory.json`。当前文档以手动 CRUD 为主流程。

## 4. 全局规则

### 4.1 存储

路径：`data/projects/{project_id}/settings.json`

```json
{
  "global_rules": "第三人称有限视角；禁止现代网络梗；打斗节奏偏快。",
  "style_preference": "文风偏冷峻写实，少用形容词堆砌。"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `global_rules` | string | **全局创作规则**：文风底线、叙事视角、禁忌、世界观底层逻辑等，整段自然语言 |
| `style_preference` | string | **文风偏好**：可与全局规则分开写，便于模板单独展示 |

创建/更新项目时可通过 API 写入；空字符串表示未配置。

### 4.2 行为约定

- 作用于 **整个项目** 的所有生成请求（只要 skill 模板引用了对应变量）。
- 以自然语言约束模型，**不做**规则优先级引擎或冲突检测（MVP）。
- 注入变量：`$global_rules`、`$style_preference`；未配置时模板侧显示为 `（无）`。

## 5. 临时规则（单章规则）

### 5.1 含义

针对 **当前这一次生成 / 当前章节** 的额外约束，例如：

- 「本章只写对峙对话，不要开打」
- 「本章结尾必须留下悬念」
- 「临时改用第一人称」

计划书中也称「单章规则」；MVP 开发计划里完整 UI 持久化列为后续项，但组装层已预留。

### 5.2 当前实现方式

| 项 | 说明 |
| --- | --- |
| 参数名 | `chapter_rules`（请求时传入） |
| 持久化 | **默认不落盘**；不写入 `settings.json` / 章节文件 |
| 模板变量 | `$chapter_rules` |
| 空值 | 替换为 `（无）` |

调用 `prompt_builder.build_context(..., chapter_rules="...")` 或 `build_from_project(..., chapter_rules="...")` 时注入。

前端典型用法：编辑页右侧 Agent 对话栏右上角「临时规则」打开遮罩层编辑 → 生成请求时随 `chapter_rules` 带上；用户可随时清空，不影响全局规则。

### 5.3 与全局规则的关系

| | 全局规则 | 临时规则 |
| --- | --- | --- |
| 作用范围 | 全项目 | 单次请求 / 当前章意图 |
| 存储 | `settings.json` | 请求参数（后续可扩展为按章持久化） |
| 变量 | `$global_rules` | `$chapter_rules` |
| 优先级 | 无引擎裁决；靠文案并列写进 user 提示词，由模型同时遵守 | 同左 |

建议在 skill 模板中同时列出二者，例如：

```markdown
全局规则：
$global_rules

本章临时规则：
$chapter_rules
```

> 注意：内置 `continue.md` 等模板目前已引用 `$global_rules` / `$style_preference`，**尚未全部引用** `$chapter_rules`。若要用临时规则，需在对应 SKILL.md 正文中加上该变量。

## 6. SKILL.md：系统提示词与用户模板

### 6.1 文件与 kind

路径：`backend/app/skills/*.md`，用户自定义在 `custom/`（同名覆盖内置）。

| kind | system | user（正文） |
| --- | --- | --- |
| `quick_action` | frontmatter **必填** `system` | 必填，含 `$变量` |
| `skill` | **禁止**使用；组装时 `system = ""` | 必填，含 `$变量` |

### 6.2 最终两条消息如何得到

```text
skill = skill_loader.get_skill(name)

if skill.kind == "quick_action":
    system = skill.system          # 来自 YAML frontmatter
else:  # skill
    system = ""

user = Template(skill.user_template).safe_substitute(context)
# context 由 build_context() 填好各 $变量
```

`model_client` 收到的形态等价于：

```json
{
  "messages": [
    { "role": "system", "content": "<system 字符串，可为 empty>" },
    { "role": "user", "content": "<渲染后的 user 字符串>" }
  ]
}
```

（具体 HTTP 封装以 `model_client` 为准；语义上就是 system + 一条 user。）

### 6.3 可用模板变量一览

由 `prompt_builder.build_context` 统一提供：

| 变量 | 含义 | 默认空值展示 |
| --- | --- | --- |
| `$global_rules` | 全局规则 | `（无）` |
| `$style_preference` | 文风偏好 | `（无）` |
| `$chapter_rules` | 临时/单章规则 | `（无）` |
| `$worldview` | 世界观记忆列表文本 | `（无）` |
| `$characters` | 人物记忆（含内嵌关系） | `（无）` |
| `$story_core` | 故事内核记忆 | `（无）` |
| `$synopsis` | 全书概要 | `（无）` |
| `$volumes` | 分卷大纲摘要 | `（无）` |
| `$previous_chapters` | 最近最多 3 章正文 | `（无）` |
| `$current_content` | 当前章节已有正文 | `（无）` |
| `$selected_text` | 编辑器选中文本（润色等） | `（无）` |
| `$user_input` | 用户补充输入（扩写、生成设定等） | `（无）` |

另可通过 `extra` 传入自定义键值，一并参与替换（模板需自行写 `$键名`）。

变量替换使用 Python `string.Template` 的 `safe_substitute`：模板里未出现的变量不影响；上下文缺少的 `$xxx` 会原样保留。

## 7. 最终提示词组成（完整链路）

### 7.1 组成关系（概念图）

```
┌─────────────────────────────────────────────────────────────┐
│ system（仅 quick_action）                                     │
│   ← SKILL.md frontmatter.system                             │
│   角色定位 + 输出约束（不重复塞记忆全文）                      │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│ user  ← SKILL.md 正文经变量渲染                               │
│                                                             │
│   [规则层]                                                  │
│     $global_rules + $style_preference + $chapter_rules      │
│                                                             │
│   [记忆层]                                                  │
│     $worldview / $characters（含关系）/ $story_core /       │
│     $synopsis / $volumes                                    │
│                                                             │
│   [短期上下文]                                              │
│     $previous_chapters + $current_content                   │
│                                                             │
│   [本次任务输入]                                            │
│     $selected_text / $user_input + 模板里的任务说明文案       │
└─────────────────────────────────────────────────────────────┘
```

**不是**「system = 规则+记忆，user = 用户一句话」这种拆法；当前实现是：

1. **system** = skill 自带的短系统提示（或空）  
2. **user** = skill 正文骨架 + 规则 + 记忆 + 章节 + 用户输入  

各 skill 按需选用变量（例如润色可能只用规则 + 选中文本 + 当前章，不必带齐全部记忆）。

### 7.2 续写（continue）实例

**system**（来自 `continue.md` frontmatter，示意）：

```text
你是一位专业小说作者……（风格一致、不重复、尊重设定、约 300-600 字）
```

**user**（渲染后示意）：

```text
全局规则：
第三人称有限视角；禁止现代网络梗。

文风偏好：
冷峻写实。

世界观与设定：
- 灵气复苏 [背景]：近十年地球灵气浓度逐年上升……

人物：
- 林砚 [主角]：边陲少年，意外获残剑……
  关系：对手→顾寒；同盟→苏晚

前文摘要（最近章节）：
### 第一章
……上一章正文……

当前章节已有内容：
……本章已写部分……

请续写当前章节的下一段，承接上文，推动情节发展。
```

### 7.3 按 kind 对照

| 组成块 | quick_action（如 continue） | skill（如 scene-beat） |
| --- | --- | --- |
| system | SKILL `system` 字段 | 空字符串 `""` |
| 规则 / 记忆 / 上下文 | 是否出现取决于 **user 模板是否写了变量** | 同左 |
| 任务说明 | 写在 SKILL 正文里 | 同左 |

### 7.4 代码入口

```python
# 1) 从项目加载上下文变量
context = build_context(
    project_id,
    chapter_id=chapter_id,
    current_content=...,
    selected_text=...,
    user_input=...,
    chapter_rules=...,   # 临时规则
)

# 2) 按 skill 名得到最终两条提示词
system, user = build(skill_name, context)
# 或一步：
system, user = build_from_project(skill_name, project_id, ...)
```

## 8. 设计原则（便于改模板时对齐）

1. **提示词模板化**：业务侧不硬编码长 prompt，一律走 SKILL.md + `prompt_builder`。  
2. **规则是自然语言文本**：全局持久化、临时随请求；不进复杂规则引擎。  
3. **记忆人类可读**：JSON + Markdown，便于备份与手改。  
4. **system 保持短而稳**：角色与输出格式；易变的设定/正文进 user。  
5. **缺省友好**：空记忆/空规则显示 `（无）`，避免模板出现大片空白造成歧义。
